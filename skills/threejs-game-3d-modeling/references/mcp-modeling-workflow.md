# Blender MCP 正式几何建模流程

本流程只覆盖正式静态几何及其模型级技术证据。阶段安排沿用[现有工作流接入约定](workflow-integration.md)，下游边界见[模型交接](model-handoff.md)。实际 Blender MCP 工具名称、参数和能力以当前会话发现结果为准。

## 开始前

- 从当前 Work Item 读取并绑定资产 ID、视觉基线、玩法用途、参考及许可、模型候选、所有权、允许修改的文件和输出位置。缺少会改变几何方案的关键信息时，先在当前 Work Item 记录假设或待解项。
- 检查并复用健康的 Blender 进程和 MCP 会话；读取版本、活动 `.blend`、场景/Collection/对象、未保存修改、外链资源和当前写者。不得重置或覆盖不属于当前任务的场景内容。
- 通过实时工具发现核验只读检查、网格编辑、拓扑、法线、UV、LOD、碰撞、保存、导出和回读能力。某项工具缺失时，只阻断受影响的正式产物及其验收，不虚构命令、检查结果或格式支持。
- 若没有可用 Blender MCP，或当前工具不能保存版本化源，正式建模保持阻断；若运行模型路线不能导出并回读 GLB，阻断该运行模型的正式交付。可继续独立的只读规格整理。不得用脚本输出、基础体拼搭或其他服务冒充正式模型。MCP 能力可用本身不增加额外确认步骤，仍按当前 Work Item 已定范围和权限执行。
- 若在 Blender MCP 会话中使用 Blender Python，先核实 Blender 版本、API、执行上下文、对象选择和模式；只在授权范围内调用 `bpy`、数学/网格操作、版本化源文件保存、模型导出及约定证据输出。不得执行 shell、网络访问、凭据或环境变量读取、任意文件读取或动态导入。Python 脚本不能绕过 Blender MCP 的可用性要求。
- 运行模型规格使用 glTF 的米制单位与 Y-up 约定，并明确模型前向轴、原点、Pivot、拆件边界和变换。导出设置与 GLB 回读都要核对坐标转换、尺度和 Pivot，不能只凭 Blender 源文件推断运行文件正确；烘焙背景源按当前工作项冻结的场景和相机约定执行。
- 按需阅读[产物目录与归档规范](../../threejs-game-architecture/references/artifact-storage.md)。源文件放在 `assets-source/<owner>/<asset-id>/<version>/`；已验收运行模型放在稳定的 `public/assets/<owner>/models/` 路径，例如 `public/assets/scenes/<scene-id>/models/<asset-id>.glb`。仅烘焙背景的 `.blend` 是可编辑源，最终图片沿既有 `decorative-full-bleed` 路线归档，不作为 GLB 登记。送审和验证文件使用现有 `evidence/<workItemId>/` 目录。工具只支持其他输出目录时，按现有归档规范处理并记录真实路径。

## 规格与制作

V1 规格至少覆盖模型用途、目标视角和观看距离、必需轮廓与结构、玩法体积、单位/坐标/Pivot、拆件边界、材质槽语义、顶点或三角面预算、适用 LOD/碰撞需求、既定交付格式与许可。运行模型使用 glTF 米制/Y-up 并交付自包含 GLB；仅烘焙背景源按冻结的场景/相机约定产出最终图片。预算依据当前项目和目标设备确定；不把示例值或 Blender 面数统计口径混为一谈。

V2 只确定建模路线，并在需要检查比例、轮廓或玩法空间时制作隔离 blockout。blockout 标明候选身份和未完成项，不能冒充正式几何，也不要求每个资产都经过 blockout。

V3 按模型需要选择硬表面、有机建模或组合方法，完成正式形体。简单或风格化设计按规格完成，不为了看起来复杂而添加装饰、高模、重拓扑、额外 UV 集或多个 LOD。

| 检查面 | 正式交付要检查并记录的事实 |
| --- | --- |
| 形体与结构 | 主要轮廓、厚度、开口、连接、拆件和玩法交互体积是否由实际几何表达；不能用材质、光照或高面数遮盖缺失结构。 |
| 拓扑与预算 | 实际对象/网格数、顶点和导出三角面统计口径、退化或内部废面、意外重叠壳及不符合需求的非流形结构；例外需说明原因。 |
| 法线 | 平滑/硬边、法线方向和需要时的切线策略是否匹配结构与目标渲染；运行模型在导出的 GLB 上复核，烘焙源按最终图片路线检查实际烘焙结果。 |
| UV | 实际 UV 通道名、用途、岛的位置与边界、接缝、拉伸/重叠和需要时的密度/Padding。报告应来自实际网格 UV 数据或可回读结果，不能用示意图代替位置报告。 |
| 材质槽 | 槽位名称、顺序和面分配作为几何交接结构记录；本技能不据此制作或验收 PBR 贴图。 |
| LOD 与碰撞 | 仅按玩法和预算需要创建。逐级记录实际网格/三角面、轮廓保留和阈值；碰撞记录形状、数量与用途。不适用时说明原因，不伪造资产。 |

保存可编辑的版本化 `.blend` 源。运行模型导出自包含 GLB，并重新读取 GLB，核对对象、网格、坐标/Pivot、预算、法线、UV 和材质槽；可用时通过 three.js `GLTFLoader` 检查资源层场景与 BufferGeometry 属性。仅烘焙背景源不要求导出 GLB；按冻结路线生成并回读最终图片。不能把 Blender 源文件上的检查直接当作运行模型导出回读或烘焙结果。

V3 的技术报告与人工检查分别记录。按需要提供模型文件、线框/UV/LOD/碰撞检查图和清楚的人工检查要点；截图由用户检查，代理不自动分析截图或代替用户判断视觉通过。发现问题后沿用当前 Work Item 的返修安排，更新候选身份并复查受影响项。

## 模型级机器核验的边界

仅对 V0 分类为运行模型的交付使用现有模型清单与静态验收器，不创建新的模型 Schema 或第二套机器验收合同：

```powershell
node <模型管线技能目录>/scripts/validate-model.mjs --repo <项目目录> --manifest <模型清单.json>
```

该脚本只报告它实际覆盖的 GLB 容器、glTF 结构、路径和预算元数据问题；它不解码并判断真实网格的形体质量、拓扑、法线或 UV 正确性。脚本通过、文件存在或清单有数值，都不能替代 Blender 检查、GLB 实际回读和人工检查。仅烘焙背景源不使用这套 GLB 验收；其运行输出由现有装饰背景图片路线验收。运行模型的运行时加载及场景消费由现有管线在 V4 提供证据。
