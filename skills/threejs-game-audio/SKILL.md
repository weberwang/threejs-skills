# three.js 音频设计

## 全局控制接入

控制面边界：可提议、可审查、可在当前用户任务的 Work Item 范围内修改，且必须回到 `$threejs-game-workflow-control` 审计和状态迁移；仅涉及外部写入、付费、真机、破坏性或外部删除、发布副作用的 A4-A6 操作请求批准。

本领域可提议、审查，并在当前用户任务、Implementation Package、A 等级与文件范围内修改。所有动作先通过 [`threejs-game-workflow-control`](../threejs-game-workflow-control/SKILL.md) preflight，结果回总控审计与状态迁移；任务内变化同步更新计划，带外部写入、付费、真机、破坏性或外部删除、发布副作用的 A4-A6 操作另行批准。

读取全局 Work Item、项目规格、资源登记和测试计划。按 F0 范围与流程、F1 规格一致性、F2 音频质量、F3 工程验证和 F4 集成/发布决策提交证据；音频方向确认不等于 A4-A6 操作批准。

1. 按核心反馈、UI、环境、音乐和可访问性定义需求。
2. 向美术接入角色提交音频资源登记包，包含来源、授权或生成记录、循环点、格式、时长、响度、用途和发布资格；由美术接入角色串行写入资源登记，避免共享文件并发写入。
3. 设计静音、分组、首次用户交互解锁、暂停恢复和页面隐藏切换；基础模块先覆盖浏览器。只有项目采用原生宿主时，才为其已选生命周期接口增加适配并在对应渠道验证。
4. 依据运行时内存、解码与加载预算，以及渠道真实音频规格选择策略；标记未授权、不可循环、解码或加载峰值过高、或不符合渠道硬限制的资源。
5. 标准、发布通道向总控提交一条音频范围、证据或阻断项，由总控更新控制面；快速通道仅在产生未决决策或阻断项时提交。

向玩法提供触发时机、分组和资源标识，向测试提供功能与预算项，向发布同步授权状态。

## 后台暂停与恢复约束

- 在基础模块阶段建立浏览器音频服务，按 `document.visibilityState` 及实际音频能力处理页面隐藏/恢复；隐藏策略按游戏暂停规则冻结音乐、音效和语音，隐藏期间拒绝过期反馈开始播放。页面生命周期不依赖 Android/iOS 专属 API。
- 音频服务记录播放实例所有权、播放位置、静音/手动暂停与页面暂停原因。页面恢复只恢复仍有效、此前因页面隐藏暂停且没有其他暂停原因的实例；不得重建已停止、销毁或所属场景已退出的实例，也不得把隐藏期间的新请求排队补播。
- 浏览器自动播放策略可能要求用户手势后恢复 `AudioContext` 或媒体播放；保留待恢复状态并在允许的用户交互/恢复事件后重试，不绕过浏览器限制、不把失败标记为成功。重复或交错的可见性/音频中断事件须幂等，监听器随服务销毁清理。
- 仅当项目明确采用 Capacitor/其他原生宿主并依赖其生命周期事件时，才增加平台适配；记录实际采用的宿主接口、触发来源与去重规则，不要求所有项目配置原生插件。
- 基础实施包和 TDD 记录音频实例所有权、播放位置、暂停原因、浏览器生命周期入口与清理策略。验证覆盖隐藏后暂停、返回后按规则恢复、重复切换不叠播、手动暂停不误恢复、已停止/销毁实例不复活、隐藏期间新请求不补播及浏览器恢复受限后的用户交互重试。源码检查或构建不能替代实际播放证据；没有运行证据时列为未验证，不得自动发起真机验收。
