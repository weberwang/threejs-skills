# three.js 制作策划

本 Skill 只负责制作领域提议、需求边界、功能契约、验收条件和交接物。它在 [`threejs-game-workflow-control`](../threejs-game-workflow-control/SKILL.md) 的 Work Item、当前用户任务和 A 等级范围内工作，并把审查结论回到控制面；不替代人工决策，不拥有状态或审批账本。

## 最短流程

1. 读取 Work Item、当前任务说明、项目配置、GDD 和适用参考证据；以 F0-F4 质量门整理最小事实。
2. 把当前任务范围拆成玩法/支持场景、玩家行为、状态迁移、依赖、正式资源边界、异常恢复和可观察验收结果；无法从静态证据判断的行为明确标为待定义。
3. 在 GDD 保持核心循环、全量场景清单、功能契约、验收条件和“需求 → 功能 → 模块 → 场景 → 资源 → 测试证据”追踪；把渠道优先级和能力开关写入项目配置。
4. 需求、产品行为或范围发生真实变化时提交 Change Request，记录影响模块、风险、新验收和用户决定请求；任务内方案和路径调整直接更新计划并重验受影响部分。

## 领域边界

- 本领域可以提议和审查需求，也可以在当前任务路径内修改规格；A3 实施包由控制面冻结后再交给 implementer。
- 无副作用本地 A4 集成可按当前任务执行；外部写入、付费、真机、发布、破坏性或外部删除等 A4-A6 操作只能由控制面建立精确 pending 并等待显式批准，本 Skill 不执行这些动作。
- 效果图或参考图只有在当前场景被指定为正式运行视觉目标时才进入视觉合同；适用时按同一场景 Work Item 的 V1→V5 证据链推进，不创建第二条生命周期。阶段与硬门以[控制模型](../threejs-game-workflow-control/references/control-model.md)和[状态、阶段与停止门](../threejs-game-workflow-control/references/state-gates.md)为准。
- 全局静态基线、场景方向和高保真证据由控制面统一校验；本领域只提供体验意图、功能事实和范围，不用文字或根摘要替代机器证据。

## 交接与收敛

制作输出只保留当前 Work Item 的状态包、GDD/契约路径、验收边界、风险、未覆盖项和下一门。事实足够且无实质取舍时停止探索；问题按 `repair`、`revalidate` 或必要的最小范围 `return` 处置，并回到控制面运行 `check`/`run`。
