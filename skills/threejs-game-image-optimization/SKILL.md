# three.js 图片资源优化

## 全局控制接入

控制面边界：可提议、可审查、可在当前用户任务的 Work Item 范围内修改，且必须回到 `$threejs-game-workflow-control` 审计和状态迁移；仅涉及外部写入、付费、真机、破坏性或外部删除、发布副作用的 A4-A6 操作请求批准。

显式调用只触发提案，不等于授权写入。所有盘点、候选生成、替换和验证都必须进入 [`threejs-game-workflow-control`](../threejs-game-workflow-control/SKILL.md)；本 Skill 不拥有全局状态或审批，不得旁路 diff 审计与证据门。

在保持 UI 图像与 3D 材质表现、运行时行为和目标浏览器/GPU 兼容性的前提下优化已引用的运行时图片和纹理，并给出可复现报告。此任务处理图像/贴图编码，不代替 glTF 几何简化或场景渲染性能优化。

## 执行边界

- 只有用户显式调用 `$threejs-game-image-optimization` 时才提出任务；A0-A3 写入直接依据当前任务范围，带外部写入、付费、真机、破坏性或外部删除、发布副作用的 A4-A6 操作才请求精确批准。不得因包体偏大、进入发布阶段、执行构建或运行测试而自动调用。
- 将本任务视为显式触发的资源领域任务，并按实际动作纳入 A0-A3、本地阶段与统一门；不得自动加入构建脚本、Git 钩子或 CI，也不得由发布状态隐式触发。
- 默认只处理项目内被运行时代码、资源清单、材质或 glTF/GLB 加载配置引用的 PNG、JPEG、WebP，以及已纳入项目纹理管线的 KTX2。设计源文件、参考图、审核证据、截图、测试夹具、构建产物、缓存以及未被运行时引用的素材不在范围内。未明确包含模型时，不修改 glTF 几何、UV、节点层级或动画数据。
- GIF、APNG、纹理图集、法线图、像素画、九宫格和带特殊色彩空间的图片属于高风险资源；保留其帧、像素网格、通道、边界和元数据语义，只在相应验证可执行时处理。

## 优化流程

1. 确定用户指定的目录、目标渠道、允许格式、画质底线和体积目标。未指定目录时，从资源加载代码、资源清单和构建入口反查实际运行时图片，不对项目外路径或整个磁盘做宽泛扫描。
2. 建立压缩前基线，逐文件记录路径、引用位置、格式、字节数、宽高、透明通道、动画或图集属性，并汇总总大小。使用内容哈希识别重复文件，但未经引用分析不得合并或删除。
3. 在独立候选目录生成结果，禁止直接覆盖原文件。记录优化工具、固定版本、完整参数和退出状态；优先复用项目已有工具，不为一次性任务增加运行时依赖。
4. 默认保持原格式、尺寸、方向和文件名：
   - PNG 优先执行无损元数据清理与无损压缩；只有画质底线允许且透明边缘、渐变和像素差异验证齐全时才使用有损调色板量化。
   - JPEG 仅处理不依赖透明度的图片，使用受控质量的渐进式压缩并移除非必要元数据，不改变 EXIF 方向呈现。
   - WebP 先判断是否已经接近最优；重复有损编码没有明确收益时保留原文件。
   - 只有用户允许格式迁移，且目标浏览器、纹理角色、three.js 加载器和降级策略均已验证时，才转换为 WebP/AVIF 或 GPU 纹理格式。
   - 3D 材质贴图可评估 Basis Universal/KTX2，以减少 GPU 显存和带宽；这会改变运行时格式与加载路径，必须验证目标设备支持并把 KTX2 接入实际 `GLTFLoader`/`KTX2Loader` 配置（`KTX2Loader.detectSupport(renderer)`），同步修改 glTF/资源清单与纹理引用。不能把 KTX2 当成可由浏览器直接展示的普通图片。
   - 精灵表、纹理图集、九宫格和像素画不得缩放、裁切、补边、重排或改变帧坐标，只允许压缩其图像容器。
5. 对每个候选执行结构与画质验证：解码成功；宽高、方向、透明度、帧数和图集坐标保持一致；无损候选比较解码后像素；有损候选检查透明边缘、渐变、文字、细线、像素网格和代表性放大差异。材质贴图还要在真实 UV、过滤/mipmap、透明、光照和材质参数下检查接缝、法线/粗糙度等数据图、色彩空间与远近采样；压缩纹理确认转码器/设备输出格式和显存收益。证据不足时保留原文件并标记“未验证”。
6. 在 three.js 中实际加载受影响资源，并验证每个主要引用材质/场景的代表状态；涉及图集、九宫格、像素画或动画时验证对应运行状态。随后运行受影响测试和生产构建，确认无加载/路径错误、错误色彩空间、材质采样异常、纹理转码失败或候选文件误入构建。
7. 只有候选体积更小且全部适用验证通过时才替换原文件；任一验证失败、体积不降或收益不足以抵偿画质与兼容风险时保留原文件。替换后再次核对引用与版本控制差异，确保修改范围仅包含获准资源及必要引用。

## 结果报告

在用户指定位置或项目既有证据目录写入报告；两者都不存在时直接在任务结果中提交，不擅自创建长期流程文档。报告至少包含：

- 优化范围、排除项、目标浏览器/GPU、Renderer 类型、工具版本与参数；
- 每个文件的原始大小、优化后大小、节省字节数与比例，以及保留或拒绝原因；
- 总体积前后对比，分别列出源资源与生产构建中的实际变化；
- 结构、UI/材质画质、three.js 加载、纹理转码、显存/带宽影响、测试和生产构建证据；
- 格式迁移产生的引用修改、未验证项、剩余风险和回退方式。

不得用“命令成功”代替画质与运行验证，也不得在缺少压缩前基线时声称已节省体积。
