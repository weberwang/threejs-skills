# SDK 单文件独立初始化

当项目接入或调整任何第三方 SDK 的初始化时读取本文件。目标游戏统一使用 `src/platform/initialize-sdks.ts` 存放初始化实现；没有采用 SDK 时不创建占位文件，不因本规范增加 SDK 或依赖。

## 唯一文件与入口

- `initializeSdks(config): void` 是应用启动时唯一的 SDK 批量初始化入口，由 `src/main.ts` 在装配阶段调用。游戏首帧、Boot 和场景启动不等待该入口的批次完成，不使用 `await initializeSdks(...)` 或全局 `allSdksReady` 门。
- 所有已采用 SDK 的配置读取/校验、平台分流、导入/初始化调用、完成回调处理、幂等状态和初始化重试实现放在同一文件中。按 SDK 定义私有初始化函数和独立状态，不能只在此列一个注册表，再将实际初始化散落到广告服务、隐私模块、场景或各平台入口。
- 公共类型、纯配置定义、原生插件安装与必要宿主配置可归属原有文件；SDK 的业务能力和运行期适配继续各自分层，不把广告展示、支付、登录 UI、埋点业务或隐私弹窗实现集中到初始化文件。业务层仍通过公开能力接口调用，不直接导入原生 SDK。
- Android/iOS/Web 分流在同一文件内按已采用目标和能力选择；不支持的平台明确跳过，不导入或调用该平台不可用的原生 SDK。SDK 默认导入不能在文件顶层产生初始化副作用，也不能让某个可选 SDK 的模块加载错误导致整个初始化入口不可执行。

## SDK 之间无前置依赖

1. 每个启用 SDK 都从统一入口独立投递自己的初始化任务。单个 SDK 的异步导入、同步抛错、配置失败、拒绝、重试或永不回调，都不能阻止其他 SDK 的任务发起；每个任务内部独立捕获错误，拒绝必须被消费。
2. 禁止跨 SDK 的 `await A(); B()`、Promise 链、`dependsOn` 图、等待所有 SDK 成功的 `Promise.all` 启动门，或在 A 的成功回调内才初始化 B。即使使用 `Promise.allSettled` 汇总诊断，也只能在所有独立任务已发起后进行，不能作为启动、其他 SDK 或游戏首帧的前置。
3. 对已核实支持独立时序的接入组合，不额外等待隐私弹窗、CMP/UMP/ATT、登录、广告加载、正式场景或 UI 就绪后才发起 SDK 初始化；MAX 等其他 SDK 的完成结果也不作为隐私流程启动的前置。官方明确要求的初始化前提不能绕过；接入组合无法满足独立时序时，仅对该 SDK 返回配置限制，不建立等待另一个 SDK 或 CMP 的全局启动链。隐私相关 SDK 若确实被项目采用，其初始化同样登记在统一文件，隐私交互与授权结果由隐私模块独立处理，交互自身所需的官方就绪条件仍须满足。
4. 每个 SDK 只检查自身真实需要的平台、有效配置、原生桥/宿主等条件；条件暂未满足时仅保留该 SDK 的待初始化意图，不让其他 SDK 陪同等待。这里不移除 SDK 的库依赖或官方必需的运行条件；若锁定 SDK/插件明确要求跨 SDK 串行或等待同意，则报告具体限制及来源，在解决前将该 SDK 标为未满足独立初始化，不伪造成功、不绕过限制，也不阻塞其他独立 SDK。
5. 广告加载/展示、支付、跟踪等实际业务动作仍按各自能力合同检查 SDK 就绪、真实隐私状态和操作条件；去掉初始化耦合不代表允许提前发起这些动作。某能力未就绪时在其公开入口返回当前状态，不建立全局启动屏障。

## 状态与失败隔离

- 每个 SDK 只有一个初始化状态所有者；同一配置的重复启动复用自己的进行中请求或当前结果，不重新初始化其他 SDK。只有实际 SDK 完成回调或其官方完成信号才确认成功，不能把请求已受理、任务已投递或另一个 SDK 成功当作成功。
- 每个 SDK 独立持有初始化请求标识、失败原因、重试计数、deadline 与 timer；具体可重试分类和退避使用该 SDK 已确定的合同，不额外创造全局重试循环。只重试目标 SDK，不重新执行整个 SDK 列表，手动重试与自动恢复复用同一任务。
- 配置替换、禁用或销毁时只取消对应 SDK 的初始化恢复任务，并使其旧回调失效；迟到或重复回调不能覆盖新请求或重复触发成功后的动作。SDK 相互之间不共享初始化成功标志、失败计数或重试 timer。
- 各业务能力通过状态查询或事件消费 SDK 初始化结果；由 `src/main.ts` 按公开契约注入查询、结果通知和单 SDK 重试能力，业务门面不得反向导入平台初始化文件。已有 `initialize`/`retryInitialize` 适配契约的实际 SDK 调用和恢复状态也必须落在统一文件，门面仅转发已注入的目标 SDK 入口，不另建初始化实现或状态机。MAX 初始化恢复与广告位加载恢复分属不同任务，后者继续由广告服务逐广告位持有。
- 初始化诊断记录 SDK 身份、平台、当前阶段和脱敏结果；不记录 SDK 密钥、凭据、设备标识或完整原生异常。单个 SDK 失败只影响依赖该 SDK 的能力，不修改其他 SDK 的状态。

## MAX 与 AppsFlyer

- MAX 初始化任务按[广告接入合同](../../threejs-game-ad-integration/references/applovin-max-contract.md#初始化与隐私独立编排)完成内建 Terms and Privacy Policy Flow 的关闭配置，并在新 SDK 实例首次实际 initialize 前手动调用 `AppLovinMAX.setHasUserConsent(false)`，再正常调用 initialize；不能只设置业务变量或依赖 SDK 默认值。官方 Cordova 未提供流程开关时从受支持的宿主配置取消 opt-in，不编造运行时方法；设置 false 也不能代替关闭流程。初始化成功仍以实际完成回调确认。
- `hasUserConsent=false` 是传给 MAX 的初始化隐私配置，不是广告可用性状态；广告服务不能因该值跳过预加载、Banner 加载、加载重试或展示，也不能将 privacy gate 映射为 pending/blocked。SDK 就绪且其他实际请求条件满足时正常请求广告；SDK/adapter 的真实拒绝和无填充按实际失败处理，不改成 true、不删除真正的请求限制来伪造成功。
- 项目已启用 AppsFlyer 时，在同一文件中独立实现其初始化与启动。按[官方 Cordova 初始化指南](https://github.com/AppsFlyerSDK/appsflyer-cordova-plugin/blob/master/docs/Guides.md#init-sdk)核对锁定插件：当前官方调用链在 AppsFlyer 自己的 `init()`、配置与监听登记后，由 `registerSessionReadyListener` 回调调用 `start()`，不能只初始化却漏掉启动，也不能重复 start。该 SDK 自身的 session-ready 与实际采用的 ATT/授权条件按官方要求处理；不把其任务挂在 MAX 初始化、MAX 隐私流程、广告就绪或全局 SDK 就绪事件下。
- MAX 与 AppsFlyer 不互相 await，不共享初始化成功标志、请求或重试任务；一个失败、被禁用或永不回调时，另一个仍独立发起并推进。关闭 MAX 内建流程不用于修改 AppsFlyer 的真实授权状态；独立隐私模块与业务使用门仍按各自能力处理。
- 只对项目实际采用的 SDK 应用上述规则，不因该组合说明安装 AppsFlyer 或增加新的原生接入。目标项目的验证分别证明 MAX 初始化完成和 AppsFlyer 已实际启动，不能用其中一个成功或入口已返回代替另一个的完成事实。

## 实施与验收

在 TDD 和实施包记录唯一文件、实际启用 SDK、各自配置来源、启动条件、真实完成信号、状态所有权、失败/重试和业务使用边界；各 SDK 不设互相依赖的初始化顺序。统一入口属于基础平台能力，具体业务接入仍遵守原工作项和视觉/发布门。

按改动推荐并执行 T0–T3 验证。目标项目的定向测试至少覆盖：

- 同时启用两个 SDK，任一个抛错、失败或不回调，另一个仍发起且能独立完成，游戏首帧不受批次状态阻塞。
- 在已核实支持独立时序的 SDK/CMP 组合中，CMP/ATT 未完成或被拒绝时初始化照常进行，受隐私约束的实际业务动作仍被正确限制；不支持的组合只阻断对应 SDK，不影响其他 SDK 或游戏首帧。
- 同时启用 MAX 与 AppsFlyer 时，验证内建 MAX 隐私流程关闭后仍收到真实 MAX 初始化完成信号；分别令任一 SDK 失败、禁用或不回调，另一个仍独立运行。AppsFlyer 按自身 session-ready 及实际采用的官方条件调用 start，不遗漏也不重复启动；无运行证据时分别标记未验证。
- 检查 MAX 在初始化前已实际调用 `setHasUserConsent(false)`；保持 false 且无其他独立阻断时，初始化成功后仍发起全屏预加载、Banner 按需加载及加载失败重试，不能等用户同意或值变 true。另测独立 SDK/平台限制仍按真实原因生效，AppsFlyer 不读取该值决定自身是否启动。
- 重复入口、单 SDK 重试、配置切换和迟到回调不造成重复初始化，不改变其他 SDK 的任务。
- Web 不调用不可用原生 SDK，禁用 SDK 不发起初始化；检查实际初始化、回调和恢复逻辑没有散落在其他文件。

本规范自身只修改 Skill 指导文件时执行文档/链接检查，不新增虚构 SDK 的占位实现或测试。未授权不运行真机、实际付费 SDK 调用、外部控制台配置或发布。
