# 产物目录与归档规范

在生成、导出、确认、接入或清理产物前读取本文件。目录按用途和所有权划分，确认状态由现有清单、人工确认与控制面记录表达，不能只凭文件夹名称判断。按需创建目录，不预建空目录，不为本规范搬迁已有有效证据。

## 存放位置

以下路径均相对目标游戏项目根目录；不是 Skill 仓库或工具安装目录。`<workItemId>`、`<stageId>` 使用现有工作项与阶段 ID，`<candidateId>`、`<version>` 在同一归属内唯一。`<owner>` 只能是 `shared`、`scenes/<scene-id>` 或 `display-layers/<display-layer-id>`；共享资格沿用[游戏项目目录规范](project-structure.md#代码归属与依赖)。

| 类别 | 默认目录 | 内容与边界 |
| --- | --- | --- |
| 临时中间文件 | `output/intermediate/<workItemId>/<stageId>/<candidateId>/` | 下载暂存、转换缓存、试切图、临时抽帧、失败导出和调试日志；仅放未被正式清单或证据引用且可再生成的文件 |
| 尚未送审的候选 | `output/candidates/<workItemId>/<stageId>/<candidateId>/` | 本地探索图、草稿、动画或音频候选；送审或成为后续输入前，先转存到下述保留目录并绑定实际路径 |
| 已确认的非运行成果 | `docs/confirmed/<owner>/<artifact-id>/<version>/` | 已确认效果图、参考目标、拆解图、布局包和设计预览；不随游戏发布，不存运行资源副本或第二套确认状态 |
| 需要保留的生产源文件 | `assets-source/<owner>/<asset-id>/<version>/` | 用户原始输入、可编辑模型/分层图、原始音频、动画源视频和必要源帧；保留用于重做、抽帧、授权和质量追溯的输入 |
| 正式游戏资源 | `public/assets/<owner>/` | 当前已验收并被游戏资源清单采用的图片、模型、纹理、音频、字体和图集；按需细分 `images/`、`models/`、`textures/`、`audio/`、`fonts/`、`atlases/` |
| 项目权威文档与清单 | `docs/` | GDD、TDD、视觉基线、资源清单、来源/许可登记与测试策略；固定文件名沿用[项目交付物规范](../../threejs-game-orchestrator/references/delivery-artifacts.md)，不复制到 confirmed 目录制造第二份权威正文 |
| 人工审阅与验证文件 | `evidence/<workItemId>/reviews/<stageId>/<candidateId>/`、`evidence/<workItemId>/validation/<stageId>/<candidateId>/` | 送审候选、未选方案的必要审计文件、截图、录屏、对照图、测试日志及报告；标明真实待确认、失败或已确认状态，证据不因尚未通过而变成临时文件 |
| 工作流机器记录 | `.workflow-control/` | 工作项、实施包、委派包、变更请求、操作审批账本、执行状态、Result 与 Evidence Manifest；使用控制工具及当前 Schema 的实际路径，不自行另建状态或审批文件 |
| 受保护的用户确认记录 | `.threejs-workflow/user-resolutions/` | 现有用户确认账本与回执的固定位置；仅由获准的编排/控制入口维护，不复制进领域归档或交给实施代理写入 |
| 可再生成构建输出 | `dist/` | Web 构建输出，不手工维护；原生构建与缓存使用已选构建工具的实际目录 |

模块导入的小型资源可随所属代码放置，但必须在 TDD 和资源清单记录唯一正式路径；同一运行资源不能在源码和 `public/assets/` 同时维护。正式资源路径按稳定所有权和资源 ID 命名，不按 Work Item、生成批次或确认日期划分；候选版本、源文件和验收记录留在对应非运行目录。

`evidence/<workItemId>/` 是项目根目录下的领域审阅/验证文件目录，不是控制面的 `evidenceRoot`。后者默认是 `.workflow-control/evidence/<workItemId>/`，用于 Evidence Manifest、`execution-state.json`、`units/<resultId>.json` 等机器工件；控制面要求位于 `evidenceRoot` 的输出和回执必须继续写入该根目录。生成器的临时转换目录可显式选择，但控制工具的同目录原子写临时文件、事务日志和测试隔离目录沿用工具实际机制，不强制改到 `output/`。

## 从生产到确认

1. **确定路径**：开始生产前在当前实施包和 TDD 的实际目录映射中写明临时、源文件、审阅、确认成果、运行资源与机器记录位置，以及文件所有者。工具支持输出参数时显式传入目标路径；工具只能写默认临时位置时，先完成归档再将其作为正式输入。
2. **保留送审对象**：未送审探索使用 `output/`。展示给用户或写入合同、清单、生成记录、确认回执前，将真实候选及必要输入保存到 `evidence/.../reviews/` 或相应保留目录；用户原始输入和不可重建的生成原件不能只存在于临时目录。后续生产所依赖的父帧、视频、参考图即使尚未确认也属于保留输入。
3. **按用途归档**：收到适用人工确认且工程检查满足后，非运行设计成果归档到 `docs/confirmed/`；正式运行资源接入 `public/assets/<owner>/`；可编辑源文件和再生产输入归档到 `assets-source/<owner>/`。不另建 `public/confirmed/` 或把整个候选目录复制进游戏资源目录。全局效果图、布局确认和资源验收沿用原门，目录整理不增加确认门。
4. **保持证据有效**：归档使用独立版本目录，不覆盖既有确认成果。同批布局 PNG、节点 JSON、决策 JSON、`review.html` 与 `generation-result.json` 整包保留，必要参考输入同样可读取。已被合同、确认账本/回执或执行状态绑定的送审文件保持原路径与实际内容；归档副本用于交付查阅，原审阅文件继续作为确认证据，不创建第二份状态。资源清单和领域文档登记正式路径、归属、来源、版本及对应确认/证据引用；受保护机器记录只通过现有控制工具维护，不手改账本消除路径差异。
5. **消费正式成果**：运行代码只从当前资源清单中的正式位置加载，不读取 `output/`、`docs/confirmed/`、`assets-source/` 或证据目录。待确认或失败候选不能因复制进正式目录而被视为通过；归档后有内容加工、重新压缩、切片或尺寸变化时，对实际交付内容补做受影响检查及适用人工验收。
6. **收尾核对**：检查正式资源无测试/预览误发布、清单无临时路径、归档引用可读取，记录实际位置和未完成项。仅对本任务无引用且可再生成的临时文件按[产物清理规则](../../threejs-game-artifact-cleanup/SKILL.md)处理；本规范不授权删除、搬迁历史记录或外部文件。

## Git 与保留

### 最小提交集

按[最小 Git 提交集](../../threejs-game-workflow-control/references/minimal-git.md)纳入运行/构建必需文件，以及当前工作项有效引用的规格、机器记录和实际产物。图片、视频、布局包、`review.html`、截图、日志和必要源输入只要仍是当前验收或续接依赖，就必须随记录精确入库；不能只提交路径字符串，或用可重新生成代替当前实际文件。

无有效引用的历史版本、重复归档和可再生成临时文件可仅本地保留；长期保存、已确认、JSON/Markdown 格式都不自动构成提交理由。账本与已冻结证据保持完整文件和原始绑定，不为缩小提交集修改确认事实。

### 提交前维护

使用[项目忽略模板](../../threejs-game-workflow-control/assets/minimal-project.gitignore)，默认忽略产物文件并保留父目录遍历，再逐文件放行当前有效依赖。执行代理递归核对实际引用和目录扫描依赖，检查最终忽略判定与暂存快照；不使用整目录放行或无差别暂存，不覆盖其他任务的精确例外。完整步骤见上述最小提交集。

### 本地保留与恢复

- Git 忽略不改变本地保留规则。不提交的文件不等于可删除；已确认、已绑定成果保持原路径和实际内容。
- 新克隆或跨机器交接必须具备当前记录实际引用的完整文件，才能运行相关文件门。秘密配置与凭据通过项目已有受控方式提供，不强制提交；缺失必需输入时报告具体阻塞，不删除引用或跳过验收。
- 新产物在送审或正式引用前进入保留目录。已有临时文件仍被有效记录引用时先保留并精确纳入续接集合；目录整理不授权迁移冻结路径或重写确认记录。
- 废弃资源、旧确认版本及未引用历史只按原清理规则处理；本规范不授权删除、取消既有文件跟踪或改写历史。
