# 九宫格 UI：拆解时确定，按小图生产

九宫格是二维纹理的呈现策略，不是 three.js 内置组件。它只适用于 HUD、DOM 控件或明确作为平面纹理使用的可拉伸皮肤；真实三维世界、角色模型和关卡不得由九宫格或整屏图片替代。V2 拆解时逐个评估底板、按钮皮肤和框体，把采用/不适用原因写入现有 `decomposition_elements[].nine_slice`，V3 按冻结参数生产，V4 使用项目已有呈现方式或实现明确的自建网格，不另增人工审批。

## 适用判断

| 元素与可观察结构 | 判断 |
| --- | --- |
| 矩形/圆角底板、弹窗框、按钮皮肤；角边细节固定，中区平坦或低频，边条可沿单轴伸长 | 通常适合；切片线避开圆角、端帽、描边转折和必须保留的阴影 |
| 可变宽高的卡片外框、输入框、列表选中底板、规则提示气泡主体 | 按实际结构选择；气泡箭头、角标和固定花纹拆为独立节点 |
| 带固定 Logo、图标、数字或文字的按钮/面板 | 只对底板皮肤使用九宫格；文字及图标独立布局，不能一并拉伸 |
| 人物、道具、完整插画、图标、字标，以及中心有不可伸长图案的材质 | 不适用；保留完整图片或拆分底板与装饰层 |
| 不规则轮廓、透视边框、连续复杂纹饰、必须保持纹理周期的表面 | 不直接拉伸；选择明确的重复纹理、自建几何或独立美术资源方案 |

不要仅凭“按钮”“底板”等名称选择。需从冻结参考图判断固定区域与可伸展区域，并保留原图外形、层次、边厚和留白。底板若由项目自建几何完整绘制，则继续使用原生绘制路线，不为九宫格改成图片。

## 冻结合同

适用时使用项目的现有合同字段：

```json
{
  "mode": "stretch",
  "reason": "圆角和边厚固定，中心为可双轴伸展的平坦材质",
  "source_size": { "width": 96, "height": 64 },
  "borders": { "left": 12, "right": 12, "top": 10, "bottom": 10 }
}
```

不适用的 UI 皮肤使用 `{ "mode": "not-applicable", "reason": "中心图案必须保持完整比例" }`。普通非 UI 插画可不声明；九宫格不能用于真实三维角色/环境，也不把 UI 底板提升为整屏背景。底板可显式声明 `element_type: "container"` 与 `render_kind: "sprite"`，由同一节点保留图片资产身份并承担布局父级职责；纯结构容器不能声明九宫格。若仍需额外纯结构容器包裹显式 Sprite 底板，必须在 `ui_layout.independent_container_reason` 说明独立职责。纹理 `source_size` 是源图像素尺寸，目标 `bounds` 是显示逻辑尺寸，两者分别冻结。

明确分类为固定图片 UI 皮肤的部件必须有上述正反决策，不能把字段缺失当作“不适用”。V2 可派生 `nine_slice_decision_required=true` 并保留到布局节点，防止投影时丢失评估要求；该标记不是手填豁免开关。

- `source_size` 是最终未裁切纹理的生产尺寸，不是场景显示框。
- 四边值是最终源帧像素；图片生产 DPR 为 1 时对应逻辑单位，尺寸和边值均为整数。纹理及每个显示框都须为中心留下正宽高，过小目标应失败，不能压缩固定角边。
- 本合同只描述四边切片；使用三边切片或重复平铺时必须另有明确项目合同，不能默认为本合同行为。
- 内部文字/图标的安全边距继续在 V2 节点目标框、父子关系和布局不变量中冻结。切片边宽不自动等于内容 padding，也不自动把空白填满。

## V2 到 V4 传递

1. **V2**：在拆解元素中记录决策，布局生成保留到对应节点。按最小显示框核对固定边和中心；同一纹理用于多个 placement 时，每个框都要满足限制。显式 Sprite 底板容器可同时作为布局父节点，不能通过包装空节点丢失其组件/placement 身份。切片线在当前拆解审阅材料中说明，并随其它拆解事实一起确认。
2. **V3**：把同一合同复制到对应组件/`expected_assets[].nine_slice`，按 `source_size` 写 `width/height` 并生产小图。普通图片仍按原尺寸合同；多组件区域不能用一个区域级声明覆盖全部资产。真实生成提示词包含小图尺寸、边宽、固定角边及独立文字/装饰要求。保持完整源纹理，禁止 trim、裁角、额外 padding 或按大显示框生产整块皮肤。
3. **V4**：正式 UI 按已冻结 `nine_slice` 选择适用的呈现路径：DOM 可使用 CSS `border-image` 或等价背景切片；WebGL 场景中的平面贴图必须由项目实现并维护分片几何（例如 4×4 顶点组成九个四边形，并同步切分 UV），也可采用九块独立平面。three.js 没有 `NineSlice` 类或内置 `setSize`/`setDisplaySize` 九宫格 API；不能假设某个 renderer 会自动切片。任何自建实现都须明确纹理、目标尺寸、UV、坐标空间和生命周期，并保持对象基础缩放不改变冻结切片边宽。
4. 调整目标尺寸或共享视口时，重算项目自建呈现数据并走既有幂等布局入口；resize/wake 不另写偏离冻结合同的底板补丁。纹理源尺寸、参数未冻结、目标过小或网格/DOM 呈现与合同不符均阻断。

机器验证合同传递、实际纹理尺寸、切片范围和实现消费；角部画质、接缝、拉伸后的材质与留白由用户人工检查。合同合法或网格构建成功不能代替视觉验收。
