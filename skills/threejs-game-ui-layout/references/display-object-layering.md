# three.js 场景层级与显示层分层

本规则适用于 three.js 世界对象、屏幕 UI、常驻 HUD 和独立 `DISPLAY_LAYER`。V1 声明真实 `Object3D` 根、Camera 和合成策略；V2 将结构意图写入布局/显示层合同；V3 按合同验收资源；V4 用正式场景运行证据确认遮挡与输入。

## Object3D 层级与枢轴

`THREE.Scene` 是 `Object3D` 场景图根节点，子对象通过 `add()` 建立父子关系。three.js 没有通用二维对象 `origin` 字段；模型枢轴由几何体局部坐标定义，需要共同旋转或缩放的子树使用父级 `Group`。可复用模型应在资源合同中说明局部原点、单位、朝向与接地点；不同原点应在导入或装配适配层处理。

- 需要围绕模型中心旋转时，让模型局部原点位于中心，或把模型放入专用 `Group` 并用子对象局部偏移定义枢轴。
- 需要脚底、车轮或工具接触点稳定时，在模型/实体合同声明该参照点与局部偏移；动画片段切换不得偷偷改变玩法碰撞体或状态所有权。
- 对 `THREE.Sprite`，合同中的二维锚点可映射到实际的 `Sprite.center`；其他 `Object3D` 的 `position` 是其局部变换原点，不代表纹理角点。布局锚点、Camera 坐标原点、模型局部原点和动画反馈偏移是不同事实，分别记录。
- 序列帧和状态图片要保持统一画布、对象中心与动作物理参照；若动作需要脚底等稳定接触点，用独立的定位参照/局部偏移表达，避免逐帧移动枢轴造成跳动。

## 显示层与实际合成

每个场景在 V1 列出需要的职责层及稳定 ID，并按场景选择 `Group`、Camera layers、独立 `Scene`、DOM Overlay 或多通道渲染。逐层声明坐标空间、Camera、深度测试/透明策略、输入归属、生命周期和负责人。场景图父子关系主要表达变换与所有权，不能单独保证最终像素前后顺序。

| 层职责 | 常见实现 | 必须明确的边界 |
| --- | --- | --- |
| 世界背景/远景 | 天空盒、雾、远景几何或世界背景材质 | 使用世界 Camera 与 world contract；交互目标应单独注册。 |
| 世界后景 | 地形、建筑、场景后部遮挡 | 使用世界坐标和深度缓冲；说明透明材质与遮挡关系。 |
| 世界主体 | 玩家、敌人、道具、交互对象 | 玩法对象、碰撞体、输入命中与资源所有者清楚。 |
| 世界前景与特效 | 前景遮挡、粒子、伤害反馈 | 声明与世界深度的关系；特效不抢交互。 |
| HUD 与常驻 UI | 信息、导航、操作控件 | DOM Overlay 或 OrthographicCamera，遵守 HUD 坐标和安全区合同。 |
| 瞬态层 | 遮罩、弹窗、抽屉、Toast | 独立 `DISPLAY_LAYER` Work Item；记录合成、输入阻断、焦点恢复和宿主关系。 |

three.js 的深度缓冲、材质透明、`Object3D.renderOrder`、Camera/Object3D `Layers` 与渲染通道共同影响画面；`renderOrder` 不是无条件压过深度测试的全局层级。需要稳定覆盖的 HUD 通常用 DOM 或单独的正交渲染通道，并清楚定义清屏、深度缓冲和 pass 顺序。多个瞬态层共存时声明互斥、覆盖顺序及最上层输入权，不能把不同父节点的局部数值直接互相比较。

布局合同中的 `regions.z_index`、`layout_nodes.z_order` 和 `display_layer_planning.inventory[].z_order` 是可审阅的层级意图，不是 Three.js API 属性。实现时映射到明确的相机/渲染通道、对象局部深度、`renderOrder` 或 DOM 层级，并以运行证据确认实际效果。V4 检查背景、世界、HUD、遮罩、弹窗及特效的同屏组合，禁止用一张整屏图代替结构化装配；至少验证代表性状态下的深度遮挡、最上层命中、关闭瞬态层后的宿主输入恢复，以及 resize 后投影与锚点稳定，并记录 Camera/合成配置和相关合同身份。
