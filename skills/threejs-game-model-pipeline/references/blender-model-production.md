# Blender 模型生产合同

适用于用户要求通过 Blender MCP 生成 three.js 三维资产。复用当前 Work Item 的基线、范围、资源清单和证据链；本合同提供领域步骤，不新增全局状态或聊天。已有模型的纯接入、压缩和 LOD 优化继续走模型管线原有流程。

## 需求与预算

从当前需求取得题材、风格、用途、尺寸/世界单位、交付格式和是否需要骨骼动画。只有影响制作的关键事实缺失时才向用户确认。已有全局视觉基线、参考图和明确预算直接复用。

建模前记录以下预算，未给出时依据实际玩法和目标平台提出具体值并写入实施包，不把示例值当作设备性能承诺：

- 每资产、每 LOD 的三角面上限；另列 Blender 多边形数，明确二者统计口径。
- 材质槽、纹理数量与分辨率、纹理显存、文件体积和预期 draw calls。
- 交互对象的 pivot、尺度、碰撞代理，以及需要时的骨骼和动画预算。

## 四步生产

| 步骤 | 当前阶段 | 执行与交付 | 完成条件 |
| --- | --- | --- | --- |
| 生成参考图 | V1 | `image_generator` 基于题材、风格与有效基线生成参考；保留实际源图、提示词、可取得的生成参数和文件路径和候选版本 | 参考身份明确，结构、比例、材质方向可用于拆解 |
| 拆解多视图 | V2 | 同一图像代理基于当前参考生成正视、侧视、后视及结构需要的俯视/三分之四视图；补充部件、尺寸关系、材质区和遮挡说明 | 各视图描述同一对象，比例一致；不可见结构标明推断，不伪装为已知事实 |
| 建模与 AI 贴图 | V3 | `gpt-6.1-sol` / `max` 建模子代理调用 Blender MCP 生成实际几何，控制面数，完成 UV、材质和必要的碰撞/LOD；图像代理生成纹理与法线所需素材 | 交付可编辑 `.blend`、GLB、贴图与清单，静态检查通过，进入待人工审查状态 |
| 人工审查模型 | V3 | 用户在 Blender 或模型查看器中检查当前候选；代理提供文件、预算统计与检查清单，按反馈修正 | 人工确认绑定当前模型和贴图路径及候选版本 后，才记录正式资源验收完成 |

多视图优先采用一致尺度、正交视角、清楚轮廓和不遮挡结构的中性背景；三分之四视图只作立体辅助。生成图之间结构矛盾时先修正视图，再依其建模。复用工作流已有 V1/V2 确认门，不为同一已确认方向重复请求确认。

## Blender MCP 执行

模型制作必须由 `gpt-6.1-sol`、`max` 推理强度的子代理执行，主代理负责方案、任务包、集成和最终验证。创建时使用 `agent_type=default`、`model=gpt-6.1-sol`、`reasoning_effort=max`、`fork_turns=none`，在消息中提供完整任务包；不使用固定其他模型的 `worker` 角色，也不使用不允许模型覆盖的完整历史继承。指定模型或强度不可用时报告限制，不静默替换。

任务包明确参考与多视图路径、当前基线、面数/贴图预算、允许修改的对象和文件、输出格式、验收标准、测试等级与命令，以及截图/真机等受保护操作的授权状态。建模子代理负责几何、UV、材质节点、贴图应用、必要的法线转换/烘焙和导出；参考图、多视图及 AI 纹理素材的生成与编辑仍委派 `image_generator`。同一模型的人工审查返修优先通过 `followup_task` 复用原建模子代理，保留预算和所有权范围。

使用当前可用的 Blender MCP 工具查询场景和 API，再执行建模。不得仅输出建模脚本、参考图或描述便宣称模型已生成。服务或桥接不可用时报告具体阻塞，继续可独立完成的参考、拆解和生产说明，不用其他未确认服务替换。

启动服务前检查是否存在同项目可复用实例，不擅自关闭用户 Blender 会话。所有对象、集合、材质和输出限制在当前任务所有权范围；保存到指定源资产目录，禁止清空整个场景或覆盖无关资产。Blender 脚本的函数、类及复杂处理使用必要的简体中文注释。

面数依据最终导出结果统计：应用相关修改器后核对实际三角化、LOD、材质拆分及导出实例，不能只报告编辑模式下的多边形数。超过预算时优先清理不可见/重复几何、减少不影响轮廓的细节或重拓扑，再按用途生成 LOD；不得用破坏轮廓、UV、骨骼权重或碰撞语义的简化伪装为达标。

## AI 纹理与法线

模型与 UV 初步稳定后，将对应 UV 布局、材质区域、接缝、纹理尺寸和参考图提供给 `image_generator`；不能把整张对象参考图直接贴到任意 UV 上。需要平铺的表面先生成无缝纹理，独特部件按实际 UV 区域制作，并保留生成源素材与应用后的贴图。

- 纹理贴图：按选定 PBR 风格生成基础颜色，避免将固定方向光照、投影或高光烘入基础颜色；需要的粗糙度/金属度按材质语义制作，不能从颜色明暗直接臆造。
- 法线贴图：交付与 UV、切线空间及目标渲染方向一致的有效法线数据。AI 直接生成的法线候选须核对通道与方向；不能把普通彩图或仅有蓝紫外观的图片当作合格法线。必要时将 AI 生成的高度细节转换或在 Blender 中烘焙，并记录来源、强度和转换/烘焙设置。
- 颜色空间：基础颜色按 sRGB 处理；法线、粗糙度、金属度等数据纹理设为 Non-Color，并通过正确节点连接。对法线记录 Y 通道方向约定，在 glTF/three.js 材质链路中核对，不盲目翻转或覆盖加载器设置。

## 验证与人工审查

技术验证前按实际改动推荐 T0–T3，说明理由、范围和命令后自动执行。在目标项目使用现有模型清单和静态验收脚本：

```powershell
node <模型技能目录>/scripts/validate-model.mjs --repo <项目目录> --manifest <模型清单.json>
```

其结果仅证明脚本实际覆盖的静态项目，不能证明视觉质量、骨骼表现或设备性能。不得为视觉验收自动启动 Blender/真机或调用截图与渲染工具；用户明确授权自动视觉验证时才执行相应范围。

提交给用户的人工检查要点：轮廓与多视图一致性、比例与尺度、前后侧结构、拓扑和面数、UV 拉伸与接缝、纹理材质分区、法线凹凸方向与伪影，以及需要时的骨骼变形、碰撞和 LOD 切换。默认直接提供模型文件和检查说明，截图或渲染图仅在明确授权范围内生成。

审查结论记录候选版本、`.blend`/GLB/贴图路径与可选追踪摘要、确认的用户反馈、问题和修复结果。用户尚未审查时保持待人工审查；修改影响几何或贴图后重新统计、重验受影响项并更新候选身份，旧确认不得用于新候选。

## 交付与接入

保留参考图、多视图、生成记录、可编辑源文件、运行模型、贴图、模型清单、静态验收报告和人工审查记录。现有模型清单用于导出资产预算；制作过程和人工反馈用当前任务的通用文件证据提交，不杜撰未经 Schema 支持的新字段。

生产单元沿用 `production_method=authored-model`、`delivery_kind=gltf-model`。该路线只为三维资产提供参考和制作输入，不把多视图当作 HUD 布局，也不把 GLB 放入二维 effect-image 的图片拆分合同。V3 人工资源验收后按适用合同进入 V4 正式场景实现、校准与 three.js 接入，检查 GLTFLoader、材质、动画、碰撞及资源生命周期；模型人工审查不替代后续运行验收。

摘要仅作为可选追踪信息，不要求提供或比对，不因缺失、错误或变化阻断验收；仍须检查模型实际内容、路径归属、资源预算和人工审查结果。
